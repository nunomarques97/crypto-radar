# Sextant reuse audit

Source: [Sextant](https://github.com/nunomarques97/sextant), commit `47cf962`, reviewed on 2026-09-14. Crypto Radar remains the primary project.

Sextant is a substantial research/backtesting system with domain/ports/engine/adapters/app boundaries, locked uv dependencies, pytest, typing/lint and import-layer checks. It has actual execution-cost and backtest accounting logic, public data acquisition and point-in-time research infrastructure. It has **no implemented general Risk Engine, real order execution, local agent runtime, or UI**. Risk and LLM ports do not establish working end-to-end integrations.

Quality below is a code-review assessment, not a blanket certification. Selected component validation: **247 tests passed in 19.34s**, using Sextant's own environment and temporary fixtures. The full Sextant suite, coverage threshold, lint/type checks and published research results were not rerun. This distinction matters.

All paths below are relative to Sextant. `tests/unit/` is abbreviated `tests/` in the test column.

**REUSE DIRECTLY: no component qualifies for immediate verbatim adoption.** Namespace coupling, type/identity gaps, different runtime semantics or unverified assumptions justify adaptation. This is a deliberate result, not a requirement to fill every category. No Sextant code has been copied into the runtime.

## Future trading design update

The continuation request adds a DESIGNED, permission-gated F0–F7 execution program. This changes future relevance, not the current runtime migration decision:

| Component | Updated future use | Safeguard |
|---|---|---|
| Exact ledger/cost/fill/holding concepts (`engine/backtest/ledger.py`, execution cost/fx/funding) | **ADAPT** when F1/F2 are separately implemented | Simulated rebalances are not exchange order/fill/reconciliation events. Add cash reservations, partial-fill identity, bot inventory ownership and native protection; preserve exact cost identities. |
| Preflight/mode/capability types | **ADAPT** for future mode composition and approval artifact | Remove automatic permission assumptions; capability means PROVED implementation for the exact account/product, not just venue enum membership. No private probe added now. |
| RiskDecision / placeholder Risk Engine | **REFERENCE ONLY** | Still no implemented sizing/protection authority to copy. Future risk implementation follows EXECUTION_ARCHITECTURE and adversarial tests. |
| DecisionRecord | **ADAPT schema concept** | Separate advisory, trade eligibility, risk permission, intent, order, fill, position and outcome IDs. Existing single record does not model ambiguous order submission. |
| Backtest point-in-time market / simulation engine | **ADAPT selected simulator contracts**, full engine **REFERENCE ONLY** | Add maker non-fill, cancel races, restarts, native-order capability and ambiguous submission; do not mistake historical fill assumptions for an execution proof. |
| Private exchange/order reconciliation/position protection | **No reusable implementation found** | Build the narrow verified adapter and deterministic lifecycle from the new design only after authorization. Do not call declarations or mocks a production implementation. |

No decisions were upgraded to REUSE DIRECTLY. No legacy source or research data was modified, and no runtime dependency on Sextant was introduced.
